# Календарь и публичная запись — передача проекта

## Состав модуля

Основной экран — утверждённый вариант «Командный центр».

Реализованные пользовательские сценарии:

1. Календарь команды и встречи выбранного дня.
2. Назначение внутренней встречи.
3. Настройка доступности через повторяющееся недельное расписание.
4. Исключения и ручная блокировка времени без создания встречи.
5. Включение, отключение и отзыв публичной ссылки.
6. Предпросмотр публичной страницы.
7. Внешняя запись: выбор дня, времени, ввод контактов и подтверждение.
8. Отображение часового пояса и правил приватности.

## Главные файлы

- `src/App.tsx` — компоненты и интерактивные состояния.
- `src/index.css` — стили и продуктовая палитра.
- `src/main.tsx` — точка входа.

## Запуск

```bash
pnpm install
pnpm dev
```

Проверка production-сборки:

```bash
pnpm build
```

## Что потребуется для production

Текущая версия является интерактивным UI-прототипом. Необходимо подключить:

- хранение рабочего расписания и исключений;
- серверный расчёт доступных слотов;
- транзакционное подтверждение слота для защиты от двойной записи;
- генерацию и отзыв токена публичной ссылки;
- создание встречи в календаре сотрудника;
- уведомления участникам;
- преобразование часовых поясов через IANA timezone;
- права доступа и аудит изменений.

## Запрос для ChatGPT

Изучи `README_HANDOFF.md`, `src/App.tsx` и `src/index.css`.

Это утверждённый модуль календаря и публичной записи корпоративной «Академии Масштаба». Сохрани существующий дизайн, палитру и информационную архитектуру. Не возвращай публичную страницу к длинному списку дат и времени.

Публичная запись должна оставаться последовательной:

1. выбор дня;
2. выбор доступного интервала этого дня;
3. ввод имени и контакта;
4. подтверждение.

Настройки сотрудника должны оставаться разделёнными на рабочие часы, исключения и управление публичной ссылкой. Существующие встречи и ручные блокировки должны автоматически исключаться из доступности. Внешнему посетителю нельзя показывать внутренние встречи, данные сотрудников и причины блокировок.

Перед изменениями опиши затрагиваемые компоненты и состояния. После изменений запусти сборку и перечисли выполненные проверки.
