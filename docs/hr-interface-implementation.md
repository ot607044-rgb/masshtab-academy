# Интерфейс Академии Масштаба

Дата: 4 октября 2026.

## Реализовано

- Светлая оболочка в стиле согласованных экранов Figma: основное меню рабочих процессов, отдельная группа управления, поиск сотрудников, уведомления, мобильное меню.
- Рабочий стол HR: вакансии, кандидаты, испытательный срок, просроченное обучение, слабые темы, ближайшие собеседования, прогресс сотрудников. Все значения берутся из API.
- Подбор: заявки, вакансии, кандидаты, пять этапов воронки, заметки, история изменений, офферы, архив. Переходы сохраняются в базе.
- Оформление кандидата сотрудником Академии: должность и отдел из вакансии, дата выхода, испытательный срок, история подбора. Повторный запрос не создает второго сотрудника; PostgreSQL блокирует строку кандидата на время операции.
- Календарь: недельная навигация, дневной список встреч, создание и отмена собеседований, длительность, ссылка на видеовстречу. Время хранится в UTC и показывается в часовом поясе браузера.
- Карточка сотрудника: маршрут из реальных назначений уроков, сроки, статусы, результаты тестов, профиль, история подбора для HR. Можно назначить опубликованный урок.
- Диагностика: последняя завершенная попытка каждого теста; средний процент по этим попыткам. Это диагностический показатель, а не присвоенная профессиональная квалификация.
- Отдельный экран квалификации со сводными результатами и фильтром слабых тем.
- Материалы/тесты и отделы/должности сгруппированы вкладками; старые URL сохранены. Раздел по должностям использует существующую матрицу знаний.
- API подбора и рабочего стола доступен HR/администратору. Карточку сотрудника видит HR, сам сотрудник или руководитель соответствующего отдела. Новые запросы ограничены `company_id`, внешние идентификаторы проверяются внутри компании.

## Таблицы

1. `recruitment_vacancies`: вакансии и заявки на подбор.
2. `recruitment_candidates`: кандидаты, этапы, история, связь с созданным сотрудником.

Миграция 009 не создает таблиц. На базе с уже прописанными uppercase enum-значениями переименование пропускается. При откате 009 нормализация enum сохраняется, поскольку старая версия ORM также ожидает uppercase.

## Проверки

Из корня проекта:

```powershell
.venv/Scripts/python.exe -m pip install -r backend/requirements-dev.txt
```

Из папки backend:

```powershell
../.venv/Scripts/python.exe -m pytest -q
```

Из папки frontend:

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd run test:e2e
```

Обычные браузерные тесты используют фикстуры только в тестовом окружении. Сквозные PostgreSQL-тесты запускаются явно, когда задан `PREVIEW_ADMIN_PASSWORD`; без этой переменной два интеграционных сценария пропускаются.

Последняя проверка: 10 backend-тестов с `-W error`, 8 browser-сценариев; production build успешен. Backend использует SQLite для изолированных API-тестов, дополнительно проверены реальные миграции и сквозной процесс на PostgreSQL 16. Предупреждения Pydantic Config/datetime.utcnow и ошибочной коллекции ORM-классов устранены. Для браузерных проверок не задавайте одновременно NO_COLOR и FORCE_COLOR.

## Предварительная версия

- Локальный интерфейс: `http://localhost:5173`.
- Backend и PostgreSQL запущены на сервере отдельным Compose-проектом `academy-ui-preview`; рабочие контейнеры и рабочие volumes не используются.
- Backend слушает только `127.0.0.1:18000` на сервере. Доступ с этого компьютера осуществляется через SSH-туннель на `127.0.0.1:8000`.
- Изолированная база: `academy_ui_preview`. Скрипт `backend/scripts/seed_ui_preview.py` отказывается работать с базой другого имени.
- Тестовый HR: `hr@preview.example.org`. Пароль в локальном `.env.preview`, поле `PREVIEW_ADMIN_PASSWORD`. Этот файл исключен из Git.
- На экране показано, что это предварительная версия с тестовыми данными. Реальные данные рабочей академии не копировались.
- Конфигурация: `docker-compose.preview.yml`. На текущем сервере исходники находятся в `/srv/academy-ui-preview-20261004`.

## Не подключено

Синхронизация HH, создание сотрудника в основной внешней CRM, OAuth/синхронизация календарей, автоматическое создание Zoom-комнат и публичная самозапись требуют реальных интеграций. Интерфейс не имитирует их работу. Встреча использует введенную HR ссылку, а новый сотрудник создается только в Академии.

Полный конструктор последовательных программ с условиями перехода и их автоматическое назначение по должности не добавлен: текущий маршрут отражает существующие назначения уроков. Автооценка текстовых ответов/кейсов и тестовое ядро этим переносом интерфейса не переработаны.

Ошибок API, JavaScript и переполнения не обнаружено. Браузерная проверка использует SSH-туннель, короткоживущий токен только в памяти и блокирует любые записывающие запросы. Для отката приложения (без удаления новых таблиц и без потери записей) на сервере:

```sh
cd /opt/masshtab-academy
docker compose -p masshtab-academy -f docker-compose.prod.yml -f /opt/backups/masshtab-academy/20261004-ui/rollback.yml --env-file .env.prod up -d --no-build backend frontend
```

Откат использует сохраненные образы и пропускает миграции старого приложения. Восстановление базы из дампа необходимо только при повреждении данных; автоматически его не выполнять. Скрипт `ops/publish-20261004.sh` одноразовый: повторный запуск прекращается, если каталог резервной копии уже существует. Полноценная будущая сборка использует обычные Dockerfile.prod; этот релиз переиспользовал проверенные backend-зависимости и nginx из предыдущих образов.
