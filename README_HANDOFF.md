# Календарь и публичная запись

Рабочий модуль встроен в существующий проект `masshtab-academy`:
FastAPI + SQLAlchemy + PostgreSQL, React + Vite. Утверждённые компоненты и
палитра перенесены из архива Figma и ограничены областью `.calendar-module`,
чтобы стили других экранов CRM не изменились.

Исходная передача из Figma сохранена в `docs/calendar/reference/`.
Описание реализации, файлов и проверок: `docs/calendar/IMPLEMENTATION.md`.

## Реализовано

- Создание, редактирование и отмена встреч с существующими пользователями CRM.
- Постоянное хранение встреч, рабочего расписания, исключений и публичных ссылок.
- Несколько рабочих окон на день недели, длительность слота и перерывы.
- Исключения для конкретных дат, включая весь день.
- Автоматическое исключение встреч и блокировок из доступных слотов.
- Публичная запись без авторизации: день → время → контакты → подтверждение.
- Включение, временное отключение и отзыв ссылки с заменой токена.
- Транзакционная защита от пересекающихся бронирований через PostgreSQL.
- UTC для моментов времени, IANA timezone для повторяющегося расписания,
  автоматическое локальное отображение в браузере, обработка переходов DST.
- Журнал событий встреч для будущей синхронизации. Внешние интеграции не подключены.

## Права и приватность

Сохранены существующие права: календарь и внутренние изменения доступны HR и
администраторам в пределах компании. Собственные настройки связаны с существующим
активным `User`, участники выбираются из CRM; новые сотрудники не создаются.
Публичное API возвращает только интервалы и квитанцию своей записи. Внутренние
встречи, списки сотрудников, контакты CRM и причины блокировок не выдаются.

## Подготовка запуска

```powershell
cd backend
python -m pip install -r requirements.txt
python -m alembic upgrade head
```

Сборка фронтенда:

```powershell
cd frontend
npm ci
npm run build
```

Примените миграцию `019` до запуска обновлённого backend. PostgreSQL — обязательная
БД для транзакционной защиты бронирований. При развёртывании обновите конфигурацию
nginx из `frontend/nginx.conf`, содержащую лимит запросов публичной записи.

В старых правилах версии `018` часовой пояс не сохранялся. Они интерпретируются
как UTC до явного сохранения настроек в нужном часовом поясе. Часовой пояс нельзя
надёжно восстановить из старых записей; администратор должен проверить эти правила.
